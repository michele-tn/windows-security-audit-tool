Windows Security Audit 2 collects technical information for reviewing Windows configuration, network settings, active sessions, privilege-escalation indicators, administrator membership, and password policies. It operates in read-only mode and does not modify accounts, services, firewall rules, or Active Directory. It does not collect passwords, hashes, authentication tokens, or private keys.

Overview

The collector creates a technical snapshot at execution time. The generated HTML5 report is standalone, works offline, and provides search, filters, collapsible sections, readable tables, and copy controls for long technical values. No audit information is transmitted to external services.

NetworkingAdapters, IP addresses, DNS servers, gateways, routes, and listening TCP ports.
FirewallStatus and behavior of Domain, Private, and Public profiles.
Local identitiesUsers, administrators, and non-secret password metadata.
Active DirectoryDomain controllers, computer inventory, administrators, password metadata, and domain policy.
SessionsActive console and Remote Desktop sessions presented in a structured table.
Privilege escalationAlwaysInstallElevated settings and potentially unsafe unquoted service paths.
Security boundary. Generated reports contain administrative metadata and may disclose internal hostnames, addresses, account names, group membership, and security configuration. Store reports securely and never commit them to a public repository.

Quick start

Prepare
Place the collector in a local directory restricted to authorized administrators.
Run
Open PowerShell with the required privileges and execute the collector.
Review
Open the HTML dashboard and retain the JSON only when operationally required.
Set-Location "C:\ProgramData\SecurityAudit"
python .\windows_security_audit2.py

By default, the collector creates two files in the current directory:

audit_result.json
audit_result.html

Custom output paths

python .\windows_security_audit2.py `
  --output "C:\AuditReports\workstation_audit"

The output argument is a base path without an extension. The example above creates workstation_audit.json and workstation_audit.html.

All paths shown in this guide are generic examples and do not identify a real environment.

Using the HTML5 dashboard

  • Use the navigation index to move directly to a report section.
  • Search for accounts, IP addresses, SIDs, ports, or configuration values.
  • Filter completed sections or sections requiring attention.
  • Expand only the information needed for the current review.
  • Copy long identifiers through the associated copy control.
  • Print or export to PDF only when organizational policy allows it.

Status meaning

StatusMeaningRecommended action
CompletedThe query returned valid dataReview the collected information
TimeoutThe component did not respond within the configured limitCheck connectivity and required services
ErrorA prerequisite or permission was unavailableReview the section error message

An Active Directory section error does not invalidate the local audit. If RSAT is unavailable or the host is not domain joined, those sections report the missing prerequisite while local sections remain usable.

Data protection

  • Do not add passwords, hashes, tokens, API keys, private certificates, or encryption keys.
  • Do not hard-code real hostnames, domains, addresses, shares, or internal URLs.
  • Do not add customer names, user names, service accounts, or organization-specific identifiers.
  • Do not commit generated JSON or HTML reports.
  • Do not commit logs, diagnostic dumps, executables, or environment files.
  • Review the complete Git history before making the repository public.
Important. The collector source may be published only after an explicit security and privacy review. Generated reports must always remain outside the public repository.

Troubleshooting

Active Directory sections report an error

Install RSAT, confirm domain membership, and use an account with appropriate read permissions.

Some local information is unavailable

Run the collector from an elevated PowerShell session. Do not disable security controls.

A section reports a timeout

Check connectivity, required PowerShell modules, and domain service availability.

The HTML report does not reflect the latest collector

Generate a new report after updating the Python file. Existing reports are static and are not updated automatically.
